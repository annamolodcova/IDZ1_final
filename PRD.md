# PRD: «Карьерный дневник»

**Версия:** 2.2 (итоговый релиз: профили + внешний каталог)
**Дата:** 2026-11-18
**Статус:** реализовано и проверено
**Стек:** React + Vite (JavaScript/JSX) + sql.js (SQLite в браузере)

---

## 1. Для кого и какую задачу решает

**Аудитория:** студенты и начинающие специалисты (junior, стажёры), которые одновременно откликаются в 5–20 компаний и проходят несколько этапов отбора параллельно.

**Боль:** информация об откликах вместе с дедлайнами тестовых и датами собеседований теряется в заметках или мессенджерах. Забывается, на каком этапе какая вакансия, что нужно сдать на этой неделе и куда писать, если ответа нет.

**Задача:** один локальный список вакансий, где по каждой видно текущий этап и ближайшую дату, а список отсортирован так, что «что горит» — сверху.

**Ограничение:** однопользовательское приложение без регистрации и сервера. Данные лежат в локальной базе SQLite в браузере; сеть нужна только для необязательного автозаполнения вакансии с hh.ru.

---

## 2. Основной пользовательский сценарий

Студент открывает приложение → нажимает «+ Вакансия» → заполняет карточку (компания, должность, статус и дедлайны) → сохраняет и видит карточку в списке с датой и подсветкой «через 2 дня» → меняет статус по мере прохождения этапов и удаляет отказ.

**Функции сценария (5):** создание · просмотр в списке · редактирование/смена статуса · видимость ближайшей даты · удаление.

**Дополнительные сценарии итогового проекта:** вход в профиль и регистрация · разные профили с отдельными списками вакансий · обзор дедлайнов на полгода в календаре · автозаполнение карточки по ссылке hh.ru · поиск вакансий во внешних каталогах без ключа API · отмена удаления · экспорт и импорт JSON в настройках · работа с клавиатуры.

## 3. Экраны и элементы интерфейса

### 3.1 Выбранный вариант: один экран + модальное окно формы

```
┌ Карьерный дневник ───────────────────────── [+ Вакансия] ┐
│ [поиск…]  [Все 6] [Отклик 2] [Скрининг 1] …               │
│ Всего: 6 · Просрочено: 1                                  │
│ ┌───────────────────────────────────────────────────────┐ │
│ │ Яндекс · Стажёр-аналитик                     [Тестовое] │ │
│ │ Тестовое: сегодня      Собеседование: 20 ноя           │ │
│ │ https://…                        Изменить      Удалить  │ │
│ └───────────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────┘
```

Схема условна. Фильтр статусов — Apple Segmented Control; действия карточки — текстовые кнопки в футере; визуальные детали — по `DESIGN.md`. В фильтре используется короткая подпись «Тестовое», в бейдже и форме — полное «Тестовое задание».

Справа от поиска — такой же Segmented Control «Список / Календарь»: он переключает представление данных; активные фильтры с поиском продолжают действовать.

В шапке справа — кнопка профиля с именем пользователя (открывает настройки) и кнопка «+ Вакансия». До входа показывается отдельный экран авторизации.

### 3.2 Связанные состояния одного экрана

1. **Список** — карточки вакансий, тулбар (поиск + фильтр по статусу + счётчик «Всего» / «Показано N из M»).
2. **Пустое состояние** — текст «Пока ни одной вакансии», кнопки «Добавить первую» и «Загрузить примеры», подсказка про локальное хранение и демо-данные.
3. **Модальное окно формы** — создание и редактирование (одна форма, поля предзаполнены при редактировании).
4. **Диалог подтверждения** — удаление и закрытие формы с несохранёнными изменениями.
5. **Пустой результат фильтра** — «Ничего не найдено» + кнопка «Сбросить фильтры».
6. **Уведомление об успехе** — «Вакансия добавлена» / «Изменения сохранены» / «Вакансия удалена» + подсветка изменённой карточки и прокрутка к ней.
7. **Уведомление с действием** — после удаления та же полоса содержит кнопку «Отменить», возвращающую вакансию в течение 6 секунд.
8. **Календарь** — теплокарта на полгода вместо списка: цвет клетки дня, панель деталей выбранного дня, легенда.
9. **Загрузка базы** — краткое состояние «Загрузка базы данных…», пока SQLite открывается; пустое состояние не мигает.
10. **Подтверждение импорта** — диалог «Заменить все вакансии?» с числом записей из файла.
11. **Экран входа** — карточка с сегментами «Вход / Регистрация», полями почты и пароля, кнопкой демо-входа и подсказкой о локальном прототипе.
12. **Настройки** — модальное окно: профиль (имя, почта), данные (экспорт/импорт), хранилище, выход из профиля.
13. **Поиск вакансий** — модальное окно для поиска по открытым каталогам и добавления найденных вакансий в дневник.

### 3.3 Элементы карточки

- компания, должность;
- бейдж статуса с цветом;
- бейдж дедлайна тестового;
- бейдж даты собеседования;
- относительная подпись («сегодня», «завтра», «через 3 дн.», «просрочено на 2 дн.») и рядом календарная дата («· 17 нояб.»);
- для прошедшего собеседования — нейтральная подпись «прошло N дн. назад» вместо «просрочено»;
- ссылка на вакансию (если указана; при отсутствии строка не показывается);
- кнопки «Изменить» и «Удалить».

| Поле | Тип | Обязательное |
|---|---|---|
| Компания | text | да |
| Должность | text | да |
| Статус | select (по умолчанию «Отклик») | да |
| Дедлайн тестового | date | нет |
| Дата собеседования | date | нет |
| Ссылка на вакансию | url | нет |
| Заметки | textarea | нет |

Над заметками — блок автозаполнения: поле «Ссылка на hh.ru» и кнопка «Загрузить» (см. §6.1). Поле необязательное и не сохраняется в вакансии.

Кнопки «Сохранить» / «Отмена».

### 3.5 Экран входа и регистрации

| Поле | Тип | Обязательное |
|---|---|---|
| Имя | text | да, только при регистрации |
| Почта | email | да |
| Пароль | password | да, не короче 6 символов |

- Сегменты «Вход / Регистрация» переключают режим, поля не сбрасываются.
- Ошибки показываются под полем (имя, почта, пароль) или полосой над формой (неверный пароль, занятая почта).
- Кнопка «Войти в демо» создаёт и открывает демо-профиль `anna@example.com` / `demo1234`.
- Пароль хранится только как соль и хеш SHA-256; внешних сервисов нет — это прототип авторизации.

### 3.6 Настройки

Одна модальная карточка с тремя секциями:

- **Профиль** — имя с кнопкой «Сохранить», почта и дата создания профиля (только чтение).
- **Данные** — «Экспорт JSON» и «Импорт JSON» текущего профиля; импорт заменяет список только этого профиля.
- **Хранилище** — короткое описание, где лежат данные, и предупреждение, если постоянное хранилище недоступно.
- В футере — «Выйти из профиля» и «Закрыть».

### 3.7 Поиск вакансий во внешнем каталоге

Модальное окно, которое открывается кнопкой «Найти» в тулбаре или «Найти в каталоге» в пустом состоянии.

- **Источник** — сегменты «Россия» (Работа России, вакансии РФ) и «Удалённо» (Remotive, англоязычные удалённые вакансии). Оба — открытые данные без ключа API.
- **Поиск** — поле и кнопка «Искать» (запрос от 2 символов, без поиска на каждый символ).
- **Результат** — строки: должность, компания, регион · зарплата · занятость; кнопка «Добавить».
- **Состояния** — подсказка до поиска, «Ищу…», ошибка с «Повторить», «Ничего не найдено», список и «Показать ещё» (для источника с пагинацией).
- **Дубликаты** — если ссылка уже есть у профиля, кнопка становится «Уже в дневнике» и недоступна.
- **Добавление** — создаёт вакансию со статусом «Отклик», ссылкой на первоисточник и заметками из описания; окно закрывается, карточка подсвечивается.

### 3.8 Отклонённые варианты

- **B. Master-detail** (список + боковая панель деталей) — ближе к Notion/Trello, но больше вёрстки.
- **C. Два экрана с роутингом** (`/vacancy/:id`) — лучше для роста проекта, но лишняя сложность для базового интерфейса.

Оба варианта можно вернуть на этапе доработки внешнего вида.

1. Создание вакансии через модальную форму с валидацией обязательных полей.
2. Список вакансий с сортировкой: просроченные дедлайны тестовых → ближайшие будущие даты → остальные (включая прошедшие собеседования) по времени изменения.

## 6. Где хранятся данные

**Хранение:** SQLite, скомпилированный в WebAssembly (`sql.js`). Файл базы `career-diary.sqlite` сохраняется в **OPFS** (Origin Private File System); если OPFS недоступен — в **IndexedDB**; если недоступно и это — приложение работает в памяти и показывает предупреждение. Подробное описание структуры данных вместе с реляционными связями и схемой жизненного цикла приведено в [ARCHITECTURE.md](ARCHITECTURE.md).

Сетевых запросов у хранилища нет. Единственный сетевой вызов — необязательный запрос к API hh.ru по кнопке (§6.1).

### 6.1 Схема базы (версия 2)

```sql
CREATE TABLE users (
  id            TEXT PRIMARY KEY,       -- UUID
  name          TEXT NOT NULL,
  email         TEXT NOT NULL UNIQUE COLLATE NOCASE,
  password_hash TEXT NOT NULL,          -- SHA-256 с солью, 1000 итераций
  password_salt TEXT NOT NULL,
  created_at    TEXT NOT NULL
);

CREATE TABLE vacancies (
  id                TEXT PRIMARY KEY,   -- UUID
  user_id           TEXT REFERENCES users(id) ON DELETE CASCADE,
  company           TEXT NOT NULL,
  position          TEXT NOT NULL,
  status            TEXT NOT NULL DEFAULT 'applied',
  test_deadline     TEXT,               -- YYYY-MM-DD, локальная дата без времени
  next_interview_at TEXT,               -- YYYY-MM-DD
  link              TEXT,
  notes             TEXT DEFAULT '',
  created_at        TEXT NOT NULL,      -- ISO 8601
  updated_at        TEXT NOT NULL       -- ISO 8601
);

CREATE INDEX idx_vacancies_user          ON vacancies(user_id);
CREATE INDEX idx_vacancies_status        ON vacancies(status);
CREATE INDEX idx_vacancies_test_deadline ON vacancies(test_deadline);
CREATE INDEX idx_vacancies_next_interview ON vacancies(next_interview_at);
CREATE INDEX idx_vacancies_updated_at    ON vacancies(updated_at DESC);
```

**Почему так:**

- `users` — локальные профили. Почта уникальна без учёта регистра (`COLLATE NOCASE`), пароль не хранится в открытом виде: только соль и хеш.
- `vacancies.user_id` — владелец записи. Все запросы к базе (выборка списка, счетчики, операции импорта/экспорта) фильтруются по текущему профилю, исключая доступ к чужим данным.
- `id` — UUID строкой: запись можно создать офлайн и позже перенести между браузерами без коллизий.
- Даты — `TEXT` в формате `YYYY-MM-DD`: лексикографический порядок совпадает с хронологическим, поэтому `ORDER BY` и `WHERE ... < ?` работают без функций и не зависят от часового пояса.
- `status` — строка из закрытого справочника (`applied`, `screening`, `test`, `interview`, `offer`, `rejected`); значения валидируются при чтении.
- `created_at` / `updated_at` — ISO 8601 в UTC; нужны для сортировки «остальные по времени изменения».
- Индексы закрывают все реальные запросы списка и фильтра; при десятках записей они не обязательны, но схема готова к росту.

**Версионирование.** Номер версии схемы хранится в `PRAGMA user_version`. Новая база создаётся по `src/lib/schema.sql`. База версии 1 при открытии мигрирует в версию 2: создаётся таблица `users`, у `vacancies` появляется колонка `user_id`, а записи без владельца закрепляются за демо-профилем «Анна» (`anna@example.com` / `demo1234`), чтобы данные не потерялись.

**Сессия.** Идентификатор вошедшего профиля хранится в `localStorage` (`career-diary.session.v1`). После перезагрузки страницы и повторного запуска приложения вход сохраняется; при выходе ключ удаляется. Сами данные профилей лежат в SQLite, а не в `localStorage`.

**Заготовка на будущее** (закомментирована в `schema.sql`, чтобы не тащить лишнее в первую версию): `tags`, `vacancy_tags`, `stage_history`, `attachments`, `settings` — теги направлений, а также история этапов и пользовательские настройки.

### 6.2 Автозаполнение с hh.ru

**Почему доступ к hh.ru — проблема (зафиксировано как известное ограничение):**

- Авторизованные методы требуют приложения и ключа, а приложение в кабинете hh.ru создаётся только для работодателей: самостоятельной регистрации для частного лица нет, доступ выдаётся через работодателя или поддержку. Для учебного проекта это тупиковый путь.
- Публичные методы формально работают без ключа, но закрыты DDoS-Guard: с части сетей и регионов `api.hh.ru` отвечает `403 forbidden` при любом User-Agent. CORS при этом открыт.
- Поэтому функция остаётся в коде как необязательная: если API доступен — карточка заполняется, если нет — форма показывает понятное сообщение и предлагает заполнить поля вручную. Приложение полностью работоспособно без hh.ru.


- Ссылка вида `https://hh.ru/vacancy/12345678` → ID извлекается регулярным выражением.
- Запрос: `GET https://api.hh.ru/vacancies/{id}` (публичный, без OAuth; CORS открыт).
- Маппинг: `employer.name` → компания, `name` → должность, `description` (HTML → текст) → заметки, `alternate_url` → ссылка. Статус и даты не подставляются.
- Уже введённые значения не затираются: заполняются только пустые поля; заметки — только если пусты.
- Кэш ответов 5 минут (лимит hh.ru — 120 запросов/мин). Ошибки `403/404/429` переводятся в понятный текст.
- В dev при сетевой ошибке используется прокси Vite `/api/hh`; в продакшене запрос идёт напрямую.

### 6.3 Внешние каталоги вакансий (без ключа API)

Два источника с единым интерфейсом; ключ не нужен ни одному, оба отдают `Access-Control-Allow-Origin: *`:

| Источник | Endpoint | Данные | Особенности |
|---|---|---|---|
| **Работа России** (`trudvsem`) | `GET https://opendata.trudvsem.ru/api/v1/vacancies?text=&limit=&offset=` | вакансии РФ: компания, должность, регион, зарплата, занятость, обязанности, ссылка | государственные открытые данные; отвечает медленно (5–10 с), таймаут 20 с; есть пагинация |
| **Remotive** (`remotive`) | `GET https://remotive.com/api/remote-jobs?search=&limit=` | удалённые вакансии: компания, должность, регион, зарплата, тип занятости, описание | быстрый (~0,5 с), англоязычный, пагинации нет |

**Маппинг в вакансию дневника:** компания → `company`, название → `position`, ссылка → `link`, описание с регионом и зарплатой → `notes` (обрезка 600 символов), статус `applied`, даты пустые.

**Поведение:** запрос только по кнопке (не на каждый символ), кэширование результатов на 10 минут, таймауты запросов и понятные сообщения об ошибках (нет сети, таймаут, 429, 5xx); повторный поиск не нагружает API. Дубликаты определяются по ссылке. Ничего не сохраняется, пока пользователь не нажал «Добавить».

### 6.4 Экспорт и импорт

Экспорт отдаёт файл `career-diary-YYYY-MM-DD.json` вида `{ version, exportedAt, app, vacancies[] }`. Импорт принимает тот же формат (или просто массив), нормализует записи, требует подтверждения и **заменяет** текущий список целиком.

**Статусы:** `applied` | `screening` | `test` | `interview` | `offer` | `rejected`.

**Демо-данные:** 5 записей в `src/lib/sampleData.js` — по одной на ключевые статусы, с датой в прошлом (просрочка), сегодня, +2 дня, +7 дней и без даты. Загружаются кнопкой, не автоматически.

## 8. Крайние случаи и поведение

- OPFS и IndexedDB недоступны или «подвесили» ответ → приложение работает в памяти, показывает предупреждение «постоянное хранилище недоступно».
- Сохранённый файл базы повреждён → создаётся новая база, предупреждение в консоли, список пустой, приложение не падает.
- Данных ещё нет (первый запуск) → это не ошибка: предупреждение о хранилище не показывается.
- Пустой результат поиска/фильтра → отдельное сообщение и сброс фильтров.
- Длинные названия и заметки → обрезка в карточке (CSS ellipsis), полностью видны в форме.
- Дедлайн тестового в прошлом → красный бейдж «просрочено на N дн.» и приоритет в сортировке.
- Собеседование в прошлом → нейтральный бейдж «прошло N дн. назад», в счётчик «Просрочено» не попадает.
- Битый JSON → предупреждение остаётся до первой успешной записи (добавление или «Загрузить примеры»), затем исчезает.
- Удаление → подтверждение, затем «Отменить» возвращает запись в течение 6 секунд; после перезагрузки без отмены запись не возвращается.
- hh.ru отвечает `403` (блокировка по сети/региону) → под полем понятное сообщение, форма остаётся открытой, введённые данные не теряются.
- hh.ru отвечает `404`/`429`/сетевая ошибка → соответствующие сообщения; повторный запрос через прокси только в dev и только при сетевой ошибке.
- Импорт битого или пустого файла → уведомление с причиной, текущий список не меняется.
- Внешний каталог недоступен, отвечает таймаутом или 5xx → в окне поиска ошибка и кнопка «Повторить»; ручное добавление и весь остальной сценарий работают.
- Источник отвечает медленно (Работа России) → кнопка показывает «Ищу…», подсказка предупреждает о 5–10 секундах; переключение на «Удалённо» даёт быстрый ответ.
- Дубликат ссылки при добавлении из каталога → кнопка «Уже в дневнике» недоступна.
- Неверный пароль → ошибка под полем, профиль не открывается; занятая почта при регистрации → ошибка под полем.
- Сессия ссылается на удалённый профиль → сессия сбрасывается, показывается экран входа.
- Выход из профиля → закрываются модальные окна, а фильтры с поиском сбрасываются при следующем входе.
- Пароль короче 6 символов либо некорректная почта → форма блокирует отправку.
- Поиск/фильтр в режиме календаря → календарь показывает только отфильтрованные события; при пустом результате показывается «Ничего не найдено» без календаря.

## 9. Конкретные проверки результата

1. **Создание и сохранение.** Добавить «Яндекс / Стажёр-аналитик», статус «Тестовое», дедлайн = сегодня + 2 дня. Ожидаемо: карточка в списке с оранжевым бейджем «через 2 дн.»; после F5 карточка на месте.
2. **Сортировка и фильтры.** Загрузить примеры: 3 вакансии с разными датами + 1 без даты. Ожидаемо: просроченная первая, затем ближайшие по возрастанию, без даты — в конце; фильтр «Оффер» оставляет только оффер; поиск «яндекс» — только совпадения; при пустом результате — «Ничего не найдено» и сброс.
3. **Валидация, редактирование, удаление.** Сохранить форму с пустыми компанией и должностью → ошибки, окно не закрывается; изменить дедлайн существующей вакансии → бейдж пересчитался; удалить вакансию → подтверждение, запись удаляется без возврата после F5. Плюс `npm run build` проходит без ошибок.
4. **Календарь.** Переключить «Календарь» → сетка на полгода, клетка сегодняшнего дня обведена, просроченный дедлайн красный, ближайшие два дня — warning-тинт. Клик по событию в панели дня → возврат в список, нужная карточка подсвечена и прокручена в зону видимости. Стрелки клавиатуры двигают фокус по дням.
5. **Сохранность и перенос.** Добавить вакансию, перезагрузить страницу → запись на месте (SQLite, OPFS). Экспортировать JSON, очистить список, импортировать файл → записи вернулись после подтверждения замены.
6. **Авторизация и профили.** Зарегистрировать профиль, добавить вакансию, перезагрузить страницу → вход сохранился, вакансия на месте. Выйти, войти другим профилем → его список пуст. Войти демо-профилем → видны только демо-данные. Все данные профилей — в SQLite, после перезапуска приложения на месте.
7. **Каталог вакансий.** «Найти» → источник «Россия», запрос «аналитик» → список с регионом и зарплатой; «Добавить» → карточка со ссылкой trudvsem и заметками, после F5 на месте. Переключение на «Удалённо» и запрос «developer» → быстрый ответ; повторный поиск показывает «Уже в дневнике». Запрос «ыыыыы» → «Ничего не найдено». Блокировка сети → ошибка с «Повторить», остальное приложение работает.
8. **hh.ru и пустое состояние.** Вставить некорректную ссылку hh.ru → понятная ошибка; при недоступности API форма не падает. Первый запуск → «Пока ни одной вакансии», «Загрузить примеры» даёт 5 записей в правильном порядке.

- Порт 5173 на машине занят другим проектом; проверка шла на 5199. `npm run dev` без `strictPort` сам выберет свободный порт.
- Прямой запрос к hh.ru из этой сети блокируется (`403`), поэтому успешная загрузка карточки проверена только на уровне обработки ответа и маппинга, не на живых данных. CORS у hh.ru открыт (`access-control-allow-origin: *`), прокси в dev оставлен как фоллбек.
- Headless-режим с виртуальным временем «подвешивает» Storage API — это артефакт режима; проверка сохранности выполнена через CDP с реальными таймерами.
