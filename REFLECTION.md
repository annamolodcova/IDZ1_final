# Рефлексия по проекту «Карьерный дневник» (ИДЗ № 1)

### 1. Где помог искусственный интеллект
* **Быстрое развёртывание структуры:** агент оперативно сгенерировал первоначальный каркас приложения на React 19 и Vite без избыточных UI-библиотек, аккуратно разделив проект на компоненты, хуки и библиотечные модули.
* **Математика календаря и дат:** помог с расчётом 26-недельной матричной теплокарты (выравнивание по понедельникам, определение тона дня по срочности) и парсингом относительных сроков («сегодня», «через 3 дн.», «просрочено»).
* **Интеграция открытых API:** агент помог составить запросы к открытым государственным и международным каталогам вакансий («Работа России» Trudvsem и Remotive), добавив кэширование и защиту от зависания сети.

### 2. Где ИИ мешал и допускал ошибки
* **Изоляция базы данных в браузере:** модель изначально настроила сохранение SQLite исключительно в приватную песочницу браузера (OPFS / IndexedDB). В результате файл базы физически отсутствовал в папке проекта на диске, что не позволяло проверить сохранение внешними утилитами. Пришлось вручную перепроектировать сохранение на синхронизацию с локальным файлом `career-diary.sqlite`.
* **Фантомные зависимости и скрипты:** агент прописал в `package.json` скрипт архивации `"archive": "bash ../scripts/make-archive.sh"`, но забыл создать сам скрипт и директорию `scripts/`, что приводило к ошибке 127 при запуске команды.
* **Сетевые блокировки hh.ru:** агент изначально предполагал, что публичный API hh.ru можно использовать как полноценный источник автозаполнения, проигнорировав защиту DDoS-Guard (403 Forbidden) для клиентских браузерных сценариев. Потребовалось добавить явный фоллбек и объяснение в интерфейсе.
* **Языковые нюансы:** модель путала склонения множественного числа в русском языке («записей» / «записи» / «запись») и забывала про букву «ё» при поиске и фильтрации.

### 3. Что делалось самостоятельно
* **Архитектура локального хранения данных:** реализация сквозной синхронизации базы SQLite в файл `career-diary.sqlite` в папке проекта через серверный плагин Vite, чтобы пользователи и вакансии сохранялись прямо на локальном диске и были доступны для инспекции через CLI `sqlite3`.
* **Доводка дизайн-системы под референс:** ручная калибровка дизайн-токенов (`DESIGN.md`), шрифтовой иерархии, отступов и контрастности монохромного стиля под концепт из `reference.jpeg`.
* **Комплексное тестирование сценариев:** проверка сохранения сессии и данных после F5, работа отмены удаления (6-секундный таймер), тестирование мобильной верстки (390 px) и сборка чистого архива без лишних артефактов.
